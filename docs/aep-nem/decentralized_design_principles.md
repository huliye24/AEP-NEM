# Decentralized Design Principles

AEP-NEM 的长期形态不是单一平台，而是一套开放工程协议。

## 核心原则

> 协议优先，平台其次。

任何人都可以发布 AEP，任何团队都可以组合 NEM，任何组织都可以形成自己的 E-Chain。

## 设计原则

### 1. 多中心发布

协议不要求所有 AEP 和 NEM 发布到同一个中心。每个团队可以维护自己的仓库、索引和命名空间。

### 2. 开放验证

一个 AEP 或 NEM 是否可信，不由发布者自称决定，而由 PoEW、Gate、测试、报告和可复现证据支撑。

### 3. 开放分叉

任何工程节点都可以被分叉。分叉应保留来源、版本、变更说明和新的 Gate 记录。

### 4. 开放合并

合并不应只依赖权威审批，而应依赖清晰的验收标准和可审计证据。

### 5. 可迁移格式

第一阶段优先使用 Markdown、YAML、JSON 和普通目录结构，避免过早绑定数据库或平台。

### 6. 可解释治理

每一次采纳、拒绝、暂停或发布，都应有明确原因、证据和下一步建议。

## 推荐最小实现

```text
Git repository
  + Markdown docs
  + JSON Schema
  + examples
  + Gate records
  + PoEW records
```

这个组合足以支持第一阶段的多中心协作。
