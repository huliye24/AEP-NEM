# Protocol Overview

AEP-NEM 是一套工程组织协议，用来描述 AI 原生工程中的任务拆分、任务分发、节点进化、工程链路、验证证据和采纳机制。

核心定义：

> AEP 是可分发的最小工程任务包协议；NEM 是由多个 AEP 组成并持续进化的项目节点协议。

## 为什么需要 AEP-NEM

传统工程流程常常按线性顺序推进：

```text
需求 -> 开发 -> 测试 -> 发布
```

AI 原生工程更像持续实验系统：

```text
提出假设 -> 生成方案 -> 执行任务 -> 记录证据 -> 评分/验证 -> 修复 -> 分叉 -> 采纳 -> 升级
```

AEP-NEM 的目标是让这个过程有清晰结构，而不是让任务、实验、代码、报告和判断散落在聊天记录或临时文档里。

## 基本对象

### AEP

AEP 是可分发的最小工程任务包协议。它必须能被明确描述、分发、执行、验证、回传和交付。

一个合格 AEP 应回答：

- 为什么要做？
- 做到什么算完成？
- 输入是什么？
- 输出是什么？
- 怎么验证？
- 需要留下什么 PoEW 证据？

### NEM

NEM 是由多个 AEP 组成的可进化工程节点。

一个 NEM 不只是任务集合，而是一个可以长期维护、升级、被依赖、被替换的工程能力单元。

### Gate

Gate 是采纳判断机制。它决定一个 AEP 能否进入 NEM，或者一个 NEM 能否进入更成熟阶段。

Gate 的结果应记录为 `PASS`、`FAIL`、`HOLD` 或 `NEEDS_REVIEW`。

### PoEW

PoEW 是 Proof of Engineering Work，即工程工作量证明。

它不证明“看起来做了很多”，而证明“产生了可验证工程成果”。

## 推荐流转

```text
1. 创建 AEP 任务包
2. 分发 AEP 到执行端
3. 执行端运行任务
4. 执行端生成 outputs、PoEW、Gate result 和 report
5. 执行端回传 AEP return package
6. 发起端通过 Gate 复核
7. 通过后采纳到 NEM
8. 更新 NEM 版本、成熟度和 roadmap
9. 多个 NEM 组成 E-Chain
10. 多条 E-Chain 形成 E-Organism
```

## 协议优先

AEP-NEM 首先是一套协议，而不是某个中心化平台。任何团队都可以用 Markdown、YAML、JSON、Git 和普通文件系统开始实践。

平台可以在第二阶段出现，但协议必须先能独立存在。
