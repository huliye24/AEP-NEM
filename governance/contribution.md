# Contribution Guide

## How to contribute

AEP-NEM Protocol is an open protocol. Contributions are welcome from anyone.

### What can be contributed

| Area | Examples |
|---|---|
| **Specs** | Clarifications, edge cases, new fields |
| **Schemas** | Improved validation, new schema types |
| **Templates** | Better starter templates, new template types |
| **Examples** | Real-world AEPs and NEMs from your projects |
| **Tooling** | Validators, CLIs, integrations |
| **Docs** | Translations, guides, diagrams |
| **Governance** | Versioning proposals, publishing standards |

### What should NOT be contributed (yet)

- Breaking changes to the core format without discussion
- Protocol forks that would fragment the standard
- Implementation-specific details in the protocol specs

---

## Contribution process

1. **Open an issue** describing what you want to change or add
2. **Discuss** with the community
3. **Submit a PR** with your changes
4. **Pass review** — at least one other contributor must approve
5. **Merge** — changes are merged and versioned

---

## Design principles

When contributing, follow these principles:

1. **Protocol over implementation** — Specs describe what, not how
2. **Minimal viable format** — Prefer simpler structures
3. **Backward compatibility** — Don't break existing AEPs and NEMs
4. **Machine-readable first** — Everything must be validatable
5. **Human-readable always** — A human should understand any file by reading it
6. **Decentralization by default** — Don't design in central authority

---

## Code of Conduct

- Be constructive
- Focus on the protocol, not personalities
- Assume good faith
- Design for the long term
