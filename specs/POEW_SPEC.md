# PoEW Specification v0.1

**Full name:** Proof of Engineering Work Specification
**Version:** v0.1 Draft
**Status:** Draft — open for feedback

---

## 0. Abstract

PoEW (Proof of Engineering Work) is the verifiable evidence that engineering work was performed. Every AEP execution produces a PoEW record. Every Gate evaluation produces a PoEW record. Together, they form a complete, auditable trail of engineering activity.

---

## 1. Definition

> **PoEW is verifiable evidence that engineering work was performed, including what was done, by whom, when, and with what result.**

PoEW is inspired by blockchain's proof-of-work concept but applied to engineering: the "work" is actual engineering output, not cryptographic puzzle-solving.

---

## 2. Why PoEW Matters

In AI-native engineering:

1. **Attribution**: Who (or what agent) did the work?
2. **Reproducibility**: Can the work be reproduced independently?
3. **Quality**: Did the work pass its gates?
4. **Traceability**: What chain of work led to this NEM's current state?
5. **Trust**: Can an external center verify this NEM's claims?

PoEW answers all five questions.

```yaml
timestamp: "2026-06-02T14:30:00Z"

  aep_id: "AEP-TIDE-DATA-001"
  version: "0.1.0"

  type: "ai_agent"
  model: "claude-opus-4-7"
  provider: "anthropic"

environment:
  os: "linux"
  runtime: "python-3.12"

  tasks_total: 3
  tasks_completed: 3
  tasks_failed: 0

  - path: "outputs/data_ingestion.py"
    hash: "sha256:abc123..."
  - path: "outputs/test_data_ingestion.py"
    hash: "sha256:def456..."
  - path: "outputs/schema.sql"

  - gate_id: "GATE-AEP-001"
    result: PASS

  input_hash: "sha256:jkl012..."
  output_hash: "sha256:mno345..."

signature: "auto-poew-v0.1.0"
```

---

## 4. PoEW Types

| Type | Generated By | Contains |
|---|---|---|
| **AEP PoEW** | AEP execution | Execution log, output hashes, task results |
| **Gate PoEW** | Gate evaluation | Criteria results, evidence references, evaluator identity |
| **NEM PoEW** | NEM evolution | Aggregated AEP and Gate PoEWs for a version transition |
| **E-Chain PoEW** | Chain operations | Merge results, cross-track validation |

---

## 5. Verification

A PoEW record can be independently verified by:

1. **Re-execution**: Run the same AEP with the same inputs, compare output hashes
2. **Gate replay**: Re-run gate criteria against the recorded outputs
3. **Chain validation**: Trace the full PoEW chain for a NEM from its earliest AEP

---

## 6. PoEW Chain

PoEW records form a chain:

```
POEW-AEP-001 (AEP execution)
    │
    ▼
POEW-GATE-001 (Gate evaluation)
    │
    ▼
POEW-AEP-002 (AEP execution)
    │
    ▼
POEW-GATE-002 (Gate evaluation)
    │
    ▼
POEW-NEM-v0.1.0 (NEM maturity transition)
```

Each record references its predecessor, forming a verifiable chain from the first AEP to the current NEM version.

---

## 7. Reproducibility

The reproducibility hash captures all inputs that affect the output:

```
input_hash = hash(
    agent_spec.md +
    human_brief.md +
    rules.md +
    task_map.yaml +
    input_files +
    environment_spec
)

output_hash = hash(all_output_files)
```

If the same input hash produces the same output hash across different executors, the work is reproducible.

---

## 8. Non-Goals (v0.1)

- PoEW is NOT a blockchain consensus mechanism
- PoEW does NOT require cryptographic mining
- PoEW does NOT require a distributed ledger
- PoEW is NOT a token or cryptocurrency

PoEW is an engineering audit trail, not a financial instrument.
